Specifying user-defined mediation models

Use wsMed(form = "UD", paths = ...) when the mediator connections do not match a predefined model. Supply paired raw measurements, then list the arrows among mediators and from mediators to the outcome. This tutorial uses the package’s simulated data and the default inference and reporting settings.

data(example_data)

Mediator numbering

Mediator labels are assigned according to the order of the variables supplied to M_C1 and M_C2. For example:

Construct Condition 1 Condition 2 Model label
A A1 A2 M1
B B1 B2 M2
C C1 C2 M3
D D1 D2 Y

Therefore, "M1 -> M3" represents a path from construct A to construct C. Mediator numbering identifies variables; it does not determine path direction.

Specifying a custom model

Write one directed connection per string in paths. Use the model labels M1, M2, and so on, plus Y, rather than raw column names such as A1. For example, to connect A to C, C to the outcome, and B to the outcome:

custom_paths <- c(
  "M1 -> M3",  # A to C
  "M3 -> Y",   # C to the outcome
  "M2 -> Y"    # B to the outcome
)
Entry in paths Connection in this example
"M1 -> M3" A predicts C
"M3 -> Y" C predicts the outcome D
"M2 -> Y" B predicts the outcome D

Each string represents one arrow, not a complete mediation route. For example, specify "M1 -> M3" and "M3 -> Y" separately instead of writing "M1 -> M3 -> Y". Spaces around -> are optional.

Only the listed mediator connections are included. In this example there is no direct path from M1 to Y, and no directed path between M1 and M2. Paths from the condition to every mediator, and the direct path from the condition to the outcome, are added automatically. Do not add X to the path vector.

Fitting the complete model with wsMed

Pass the path vector to wsMed() along with the paired measurements:

result_custom <- wsMed(
  data = example_data,
  M_C1 = c("A1", "B1", "C1"),
  M_C2 = c("A2", "B2", "C2"),
  Y_C1 = "D1",
  Y_C2 = "D2",
  form = "UD",
  paths = custom_paths
)
print(result_custom)

To include a direct M1-to-outcome connection, add its arrow to the vector:

expanded_paths <- c(
  custom_paths,
  "M1 -> Y"
)

Refit the same call with paths = expanded_paths to include that connection. This changes the fitted model and adds the indirect route through M1 alone.

Input requirements

  • Reference only mediator labels defined by the supplied column pairs.
  • Use one arrow per string, starting at a mediator and ending at another mediator or Y. At least one arrow must end at Y.
  • Do not repeat an arrow or use a self-loop such as "M1 -> M1".
  • Do not create a cycle, such as both "M1 -> M2" and "M2 -> M1".

Every mediator intended to contribute an indirect effect needs a route to Y, either directly or through other mediators. The package warns if a supplied mediator has no such route.

Indirect effects

wsMed() identifies all indirect routes implied by the specified arrows. In the following notation, X denotes the within-subject condition; it is not an entry to add to paths. The model defined by custom_paths contains three indirect effects:

Route Parameter label Product
X -> M1 -> M3 -> Y indirect_1_3 a1 * b_1_3 * b3
X -> M2 -> Y indirect_2 a2 * b2
X -> M3 -> Y indirect_3 a3 * b3

The last effect exists because the path from the condition to every mediator, including \(M_3\), is added automatically. All identified indirect effects are summed to form total_indirect, and the total effect is defined as cp + total_indirect.

Parameter labels

The generated model uses the following labels:

Path Difference component Level component
\(X \rightarrow M_i\) ai –
\(M_i \rightarrow Y\) bi di
\(M_j \rightarrow M_i\) b_j_i d_j_i
\(X \rightarrow Y\) cp –

For example, the path \(M_1 \rightarrow M_3\) uses b_1_3 and d_1_3, whereas \(M_3 \rightarrow Y\) uses b3 and d3.

Add a moderator

Keep form = "UD" and the same custom_paths. Add W to identify the between-subject moderator column and MP to select the path coefficients to moderate. You do not need to construct product terms yourself.

Argument What to supply Example
paths The mediator connections in the model custom_paths
W The moderator’s column name in the data "D3"
MP Coefficient labels for the selected paths c("b_1_3", "b3")

Choose the moderated paths

paths uses arrows such as "M1 -> M3", whereas MP uses coefficient labels such as "b_1_3". For the current custom model:

Path to moderate Entry in MP Meaning
M1 to M3 "b_1_3" The M1-difference slope in the M3-difference equation varies with W.
M3 to the outcome "b3" The M3-difference slope in the outcome equation varies with W.
M2 to the outcome "b2" The M2-difference slope in the outcome equation varies with W.

Thus, MP = "b3" selects only the M3-to-outcome slope, while MP = c("b_1_3", "b3") selects both slopes along the M1-to-M3-to-outcome route. To add moderation of the M2-to-outcome slope, use MP = c("b_1_3", "b3", "b2"). Each label must exist in the model: "b1" is unavailable here because "M1 -> Y" is absent from custom_paths. Do not put an indirect-effect label such as "indirect_1_3" in MP; select the coefficients that form that effect.

The corresponding average-component slopes can be selected with "d_1_3", "d3", and "d2". These are distinct coefficients: selecting "b3" does not also select "d3".

The condition-to-mediator labels "a1", "a2", "a3", and the direct-effect label "cp" are also accepted. With W present, wsMed includes its main effect in every mediator-difference and outcome-difference equation. Consequently, these condition effects can vary with W even when their labels are omitted from MP. For the b and d slopes, MP controls which interaction terms are added.

Fit and read the results

Here, D3 is a continuous moderator. This call selects the M1-to-M3 and M3-to-outcome slopes and keeps the default Monte Carlo CIs and unstandardized output:

custom_moderated <- wsMed(
  data = example_data,
  M_C1 = c("A1", "B1", "C1"),
  M_C2 = c("A2", "B2", "C2"),
  Y_C1 = "D1",
  Y_C2 = "D2",
  form = "UD",
  paths = custom_paths,
  W = "D3",
  MP = c("b_1_3", "b3")
)
print(custom_moderated)

For this continuous moderator, the default tables evaluate effects at the centering reference shown in the output. The default plot instead shows the indirect effects across the observed moderator range:

plot(custom_moderated)
plot of chunk custom-moderation-plot

Each indirect effect uses all coefficients along its route, evaluated at the same moderator value. For example, indirect_1_3 combines the condition-to-M1, M1-to-M3, and M3-to-outcome coefficients. The total indirect effect includes all routes in custom_paths, including those without a selected b-path interaction. A model that includes moderation need not show evidence that an effect varies; interpret the estimates and their uncertainty.

The name D3 in at must match the column supplied to W. Supply values on the original scale, even though wsMed centers continuous moderators internally. Choose values that are meaningful for your study and supported by the data. Changing at reuses the fitted model and inference draws. See Read and export results for selecting and comparing effects.

Use a categorical moderator

The same paths and MP specification works with a binary or multicategory moderator. Store it as an unordered factor with the desired reference group as its first level, then supply its column name through W; for example, use W = "Group" if that factor is named Group. The default tables report effects for all observed groups, and plot() displays group-specific effects with CIs. The categorical predictor tutorial shows how to declare the factor and compare groups.

Optional: inspect the generated equations

The call to wsMed() performs data preparation and model generation for you. Use printGM(result_custom) to inspect the fitted model specification. If you want to generate the equations without fitting, the lower-level functions below provide that option.

PrepareData() converts the raw condition-specific variables into mediator difference and centered level components and an outcome difference score.

prepared_data <- PrepareData(
  data = example_data,
  M_C1 = c("A1", "B1", "C1"),
  M_C2 = c("A2", "B2", "C2"),
  Y_C1 = "D1",
  Y_C2 = "D2"
)

names(prepared_data)
#> [1] "Ydiff"  "M1diff" "M2diff" "M3diff" "M1avg"  "M2avg"  "M3avg"

For mediator \(M_i\), the two components are

\[ M_{i,\mathrm{diff}} = M_{i2} - M_{i1} \]

and

\[ M_{i,\mathrm{avg}} = \widetilde M_{i,\mathrm{avg}}-\overline{\widetilde M}_{i,\mathrm{avg}}, \qquad \widetilde M_{i,\mathrm{avg}}=\frac{M_{i1} + M_{i2}}{2}, \]

where the bar is the sample mean used by PrepareData() to center the average component. The difference component is not centered.

The corresponding model syntax is generated as follows:

custom_model <- GenerateModelCustom(
  prepared_data = prepared_data,
  paths = custom_paths
)

cat(custom_model)
#> Ydiff ~ cp*1 + b2*M2diff + d2*M2avg + b3*M3diff + d3*M3avg
#> M1diff ~ a1*1
#> M2diff ~ a2*1
#> M3diff ~ a3*1 + b_1_3*M1diff + d_1_3*M1avg
#> indirect_1_3 := a1 * b_1_3 * b3
#> indirect_2 := a2 * b2
#> indirect_3 := a3 * b3
#> total_indirect := indirect_1_3 + indirect_2 + indirect_3
#> total_effect := cp + total_indirect

For every specified structural edge, the generated regression includes both the difference and level components of the predictor mediator. Thus, "M1 -> M3" contributes

b_1_3*M1diff + d_1_3*M1avg

to the regression equation for M3diff.

Only specified structural paths are added. Because "M1 -> Y" is absent from custom_paths, M1diff and M1avg do not appear directly in the regression equation for Ydiff.
